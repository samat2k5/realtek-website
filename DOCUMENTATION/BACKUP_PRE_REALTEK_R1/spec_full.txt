Upgrade the existing REALTEK ENGINEERING PTE. 16. React / Tailwind Implementation Guidance
Use reusable components: Header, Hero, SectionHeading, ExpertiseCard, SaaSProductCard, ProjectCard, ContactCTA, Footer.
Keep content in data objects where practical so cards can be maintained without duplicating markup.
Use semantic HTML: header, nav, main, section, article, footer.
Use real links for navigation rather than click handlers where possible.
Use accessible button/link focus states.
Use responsive Tailwind classes rather than hard-coded desktop-only dimensions.
Avoid large client-side dependencies for simple effects.
Lazy-load below-the-fold images where appropriate.
Do not expose secrets, API keys or private application endpoints in the website source.
Keep the public corporate site separate from the authenticated ezyHR application.

18. Accessibility Requirements
All meaningful images require descriptive alt text; decorative images should use empty alt.
Maintain sufficient text/background contrast.
Keyboard navigation must reach every interactive element.
Visible focus states are required.
Do not rely on color alone to communicate status.
Use correct heading hierarchy: H1 → H2 → H3.
Use accessible mobile navigation with aria-expanded/aria-controls.
External links should be clear to users; mailto and tel links should work.
19. Performance Requirements
Optimize hero background image and use modern formats such as WebP/AVIF where supported.
Avoid shipping unnecessary JavaScript for static sections.
Set image width/height or aspect-ratio to reduce layout shift.
Target strong Core Web Vitals on mobile.
Avoid autoplay video unless it materially improves the experience and is optimized.
Use caching/compression/CDN features available on the hosting platform.
20. Security / Deployment
HTTPS must be enforced.
Do not place Resend, Zoho, database, Railway, JWT, encryption or other private application secrets in the corporate website repository.
Corporate website and ezyHR backend should have separate environment variables and deployment credentials.
Enable security headers where practical: Content-Security-Policy, X-Content-Type-Options, Referrer-Policy and appropriate frame protections.
Keep dependencies patched.
Forms should have server-side validation and spam protection.

The site is being upgraded partly to create a clear public relationship between the legal entity and EZY SaaS/ezyHR. Apple requires an organization's website to be publicly available, functional and associated with the organization; Apple also requires a D-U-N-S number and an organization-domain work email. cite markers are intentionally omitted from this developer document; see official links below.

Corporate website must remain public and functional.
Use company-domain email addresses.
Make EZY SaaS/ezyHR relationship explicit.
Do not claim EZY SaaS is a separate legal company unless incorporated.
Ensure company name/address match the D-U-N-S/D&B record and the Google payments profile.
Google organization accounts require D-U-N-S and verified organization/contact information.
Before app submission, Google requires a privacy policy and Data safety information; app review may require a working demo account and access instructions.
22. ezyHR / IRAS Messaging Rule
Do not write “IRAS Certified”, “IRAS Approved” or similar wording on the website unless specifically permitted. IRAS states that qualifying as an AIS payroll software vendor means AIS submissions through the software can be accepted by IRAS; it is not an endorsement of the payroll software.
For the website, use safer wording such as: “Designed for Singapore payroll requirements” or “Being developed to support Singapore statutory payroll and AIS requirements” until the applicable IRAS validation/listing status is actually achieved.
